# Essential solution organization

Essential is the repository and root solution. Essential.Culture is its first independent module. Checkout paths are host-specific; the repository layout is independent of the original machine path. The previous Essential.Culture root was renamed with Git history and uncommitted Web adaptation work intact.

The shared naming migration on 2026-10-05 changes solution/project and physical directory identities only. The six library projects are already product-first. Tests now use Tests.Essential.Culture, Tests.Essential.Culture.Generator, Tests.Essential.Culture.WinUI and Tests.Essential.Culture.Blazor. The former Console example is Gallery.Essential.Culture because it demonstrates the core library; adapter examples use Gallery.Essential.Culture.Wpf, .Avalonia, .WinUI and .Blazor. The checked-in package-only fixture is Tests.Essential.Culture.Blazor.PackageConsumer. Explicit AssemblyName and existing RootNamespace values retain previous assembly/XAML/internal-test/public namespace compatibility. NuGet package IDs and versions are not renamed.

Open Essential.slnx for all six Culture libraries and four test projects. Open src/Essential.Culture/Essential.Culture.slnx for the focused module, or demo/Gallery.Essential.Culture.slnx for its five runnable examples. The full file tree is maintained in [1_architecture.md](1_architecture.md).

Root Directory.Build.props owns common organization, MIT license, repository metadata, deterministic builds and artifacts/packages output. Module Directory.Build.props explicitly imports the root and owns candidate Culture VersionPrefix=1.4.0 and the existing README packaging. Current tests/Directory.Build.props and demo/Directory.Build.props explicitly import the Culture module. When adding another module, give its own source/test/demo groups explicit module settings; do not put a module's version into root props.

Culture package IDs, assembly names, existing namespaces and public signatures are preserved. The 1.4.0 candidate adds language policy, eager modular composition and one-time facade configuration; the [API inventory](culture-public-api.md) describes these additions. Core and Generator remain framework-independent. Wpf, Avalonia and WinUI retain their adapter contracts; Blazor remains scoped for SSR and Interactive Server. Essential does not reference Flourish. The optional UI adapters belong to Flourish/src/Flourish.Extensions, not to Essential.

The current Git remote identifies Evigila/Essential (origin currently uses http://github.com/Evigila/Essential.git; package metadata uses HTTPS). Earlier records used Essential.Culture and Arkheide.Essential.Culture. The recreated NuGet Trusted Publishing policy must use repository field Essential, workflow filename build.yml and environment nuget; its validation awaits an authorized tag workflow. Package IDs remain unchanged. The current vX.Y.Z CI release convention still releases Culture only, reads its module props and verifies its six packages. Future modules need their own release/version configuration.

Existing human module README and docs were relocated into src/Essential.Culture, with only Demo/license links adjusted. Existing demo READMEs stayed with their demos. Generator analyzer files and buildTransitive paths were preserved. The Blazor guide's source links now target the module directory.
